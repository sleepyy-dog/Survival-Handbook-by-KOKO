## 当你开启两个VPN代理会发生什么——一个有趣的bug

小白解决一个`ERR\_NETWORK\_ACCESS\_DENIED(被禁止访问互联网)`的 bug（如下图）的过程：

![image-20251127233738139](https://sleepy-dog-1376908035.cos.ap-guangzhou.myqcloud.com/202511272337251.png)

问题的起因是我同时开启了`clash for windows`和`V2rayN`两个代理软件，一开始一切顺利，但突然出现了上图的bug，我开始以为这只是和之前我关机时没有及时关闭代理软件，导致代理配置混乱是一样的问题（这个问题并不是在每次开启代理关机时都会出现，代理软件在关机时一般也会自动删除代理设置，而当删除速度慢导致关机时删除未完成才会发生以上问题），这种错误的表现往往是无法在浏览器打开任何网站，但是wifi显示连接，同时wx这些应用还可以正常连接服务器（解释这个现象一个可能的原因是代理混乱发生在winsock中高度影响DNS解析的模块，但是wx有自己单独的一套DNS解析的方法）

这个bug的解决需要打开终端，输入以下命令然后重启即可

```powershell
netsh int ip reset c:\resetlog.txt % 重置 ip

netsh winsock reset % 重置 winsock 
```

但是我所遇到的问题和这个不同，现象上虽然wifi显示连接，但是所有的应用都无法连接到服务器。以上的操作自然也无用。

之后尝试几个`ping`命令，发现DNS是正常的，看了设置发现代理设置也是完全准确的，但是报了一个一般故障的问题。如下图：

![image-20251128000247803](https://sleepy-dog-1376908035.cos.ap-guangzhou.myqcloud.com/202511280002990.png)

也就是说，连接被我本地的一个规则拦截了，那问题出在防火墙的配置上，最终解决方案是在终端运行以下命令解决：

```powershell
 netsh advfirewall reset % 重置防火墙
```

解释这个问题的一个可能是在同时使用两个代理时，都在防火墙中设定走其隧道的规则，相互冲突，而在二者崩溃后，相应的规则还在防火墙中残余。（导致我之后把这两个客户端都删了还是没用，现在又有重新下回来累死了）
